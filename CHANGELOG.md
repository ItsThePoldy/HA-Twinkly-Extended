# Changelog

All notable changes to this project are documented here. Versions follow
[Semantic Versioning](https://semver.org/); `0.x` releases may change behaviour
between minor versions.

## [Unreleased]

## [0.5.0] - 2026-10-25

### Added
- `Delete movie` select: deletes a movie saved on the device, in the Twinkly
  app's order (LEDs off, `DELETE movies/<unique_id>`, back to the previous mode).
- `Library` select, when `/twinkly-library` is mounted: plays a recorded movie,
  uploading it first (`movies/new` + `movies/full`) if the device does not have
  it. Refuses damaged recordings and uploads that do not fit the free frames.

## [0.4.0] - 2026-10-25

### Added
- App proxy request: when `/twinkly-proxy` is a directory inside Home Assistant,
  app mode keeps an empty file named after the device's host in it while app
  mode is on, so a host-side service can follow app mode. The file is removed
  when app mode ends and at startup; an automatic pause never writes it.

## [0.3.0] - 2026-10-25

### Added
- The integration yields the device's session token to other clients. A device
  keeps one token, and the library logs in again on every 401, so polling used
  to throw the Twinkly app out within 30 s. Two token takeovers within 5 minutes
  now pause polling for 10 minutes, doubling (up to 60 minutes) while the other
  client stays. A single takeover, as one command from a wall panel causes,
  pauses nothing.
- `App mode` switch: pauses polling for 30 minutes so the Twinkly app can stay
  connected, for example to upload new effects. It also reads on during an
  automatic pause (attribute `reason`: `app_mode` or `other_client`, `until`);
  turning it off resumes polling at once. A light or mode command from Home
  Assistant ends a pause as well.

## [0.2.0] - 2026-10-24

### Added
- Predefined device effects (`effect` mode) in the light's effect list, after
  the movies. Names come from `effect_names.yaml`, one rule per device variant;
  effects of a device without a rule are listed as `Effect <n>`. Movie entries
  keep their `"<id> <name>"` form, so existing automations are unaffected.
- Diagnostics include the device's predefined effect ids and resolved names.
- Rule for the Twinkly Curtain 210 RGBW (`TWW210SPP2`).
- Packaging of the core Twinkly integration (Home Assistant 2026.10.2) as a
  HACS custom integration: manifest `version`, committed `translations/en.json`
  (generated by `script/gen_translations.py`), test suite running on
  `pytest-homeassistant-custom-component`.
- Brand assets in `custom_components/twinkly/brand/`, taken from the
  Home Assistant brands repository's `core_integrations/twinkly`.

### Changed
- `ttls` is required as `>=1.11.1` instead of pinned, so it follows the version
  Home Assistant itself installs.
